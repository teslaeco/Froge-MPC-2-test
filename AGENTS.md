- Read `docs/WORK_CHECKPOINT.md` before continuing this project.
- Inspect the current Git state and saved deliverables before repeating any generation.
- A failed ChatGPT response does not establish that source, artifacts or deployment were lost.

## Sebastian's requested work cadence
- Work in short, reviewable stages. Aim to deliver a handoff within 8–10 minutes.
- Begin a durable checkpoint after about 5 minutes of active work, after a meaningful verified change, and before starting a long operation.
- Near the end of a stage, save and report the concrete result instead of starting optional rendering, broad research or another generation.
- If the requested change still needs work, record exactly what remains and finish that stage with usable links so the user can continue in the next turn.

## Durable checkpoints

- Record completed work, checks performed, current source revision, deployed version, deliverable names and remaining tasks.

- Never record API keys, SSH keys, access tokens or signed access URLs in Git or checkpoint notes.
- Preserve the user's deployment audience and all applicable authorization rules.
